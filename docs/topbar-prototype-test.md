# 顶部状态栏网址原型测试（2026-09-29）

仅测试 MatePad Air 12 模拟器，HDC 127.0.0.1:5555；设备类型 tablet，OpenHarmony-6.1.0.115，2800×1840。未部署真机。实验阶段未修改正式 Index.ets；随后采用的正式方案见 [验证记录](verification.md#2026-09-29隐藏系统状态栏紧凑工具栏整体上移)。

## 方法

独立副本 /private/tmp/air-topbar-prototype-20260929；使用系统 ArkUI Window、LayoutPolicy.matchParent、ignoreLayoutSafeArea，将应用布局延伸到顶部。左上 110 vp 处放置宽 300 vp、高 30 vp 的网址按钮，避开时间和中央系统多窗口入口。按钮点击切换现有 48 vp 地址工具栏；返回收起。

这是可行性实验，不是成品设计：未优化输入自动聚焦、底部背景、竖屏和窗口尺寸变化；新版 API 兼容级别警告尚未处理，实验仅运行 API 23 模拟器。

## 对照结果

| 条件 | 操作 | 结果 |
| --- | --- | --- |
| 保留系统状态栏，网址放在同一高度 | 点击物理坐标 (585,43)、(350,35)、(800,65) | 可见文字，但三次均没有展开输入框，UI 树没有 TextInput |
| 同一条件 | 从 (580,20) 下拉到 (580,750) | 打开系统通知面板 |
| 只把同一个按钮移到状态栏下方 | 点击 (585,130) | 正常展开地址工具栏，UI 树出现 TextInput；返回收起 |
| 状态栏下方对照版本 | 点击中央系统多窗口按钮 | 正常显示分屏、悬浮窗、最小化等菜单；未进一步切换窗口模式 |
| 隐藏系统状态栏，按钮恢复顶部原位置 | 点击 (585,43) | 正常展开输入框，但时间、电量和顶部系统多窗口入口不再显示 |

窗口转储显示系统状态栏覆盖屏幕顶部 0..87 px 且层级高于应用。两组位置/状态栏显隐对照支持：在这个模拟器系统版本下，保留系统状态栏时，此区域的触摸被系统处理。不能由此推断所有鸿蒙版本和真机均完全相同。

## 结论

保留系统状态栏时，可以把网址文字画到该高度，但当前原型不能在此直接点击编辑。可继续设计为顶部只显示域名、侧栏提供编辑入口；或做可选的完全沉浸模式，隐藏系统状态栏后使用应用自己的顶部控件。不要直接将本实验当作默认布局发布。

截图与三个源码变体保存在 artifacts/topbar-prototype-20260929/。topbar-loaded.png 是保留状态栏的显示效果；topbar-control-expanded.png 是下方对照；topbar-hidden-status.png 是隐藏状态栏后点击成功；topbar-system-swipe.png 是通知面板。topbar-initial.png 是启动动画，不作为布局证据。

未验证网页输入跳转、视频全屏、旋转、实际分屏/悬浮窗尺寸适配或真机触摸。实验结束后恢复模拟器原版本，源项目和原安装包保持不变。
